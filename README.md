# 培训师系统

> 基于「姐妹团看板系统」的爬虫/数据层搭建的操作型系统：培训师/姐妹团绑定管理、UID 数据速查、名额与奖励判定。
> **外部系统的认证/接口/表结构/坑见 `爬虫系统上下文.md`**。

## 已有资产（从姐妹团看板系统拷贝）

- `crawler/` — 全套爬虫：自动登录（OCR）、Cookie 保活、UID 查询、bigdata 抓取、周流水/保护期/毕业追踪（硬编码 Cookie 已脱敏）
- `data/login_credentials.json` — server1 账号凭据（勿提交，已 gitignore）
- `data/cookie.json` / `data/cookie_bigdata.json` — 当前有效 Cookie（已 gitignore）
- `data/schema.sql` + `data/stats.db` — 表结构 + 历史数据（20MB，含 team_detail 全量快照）

## 环境搭建

```bash
python -m venv .venv
.venv/Scripts/pip install -r requirements.txt   # Windows
```

注意：`requirements.txt` 必须保持 ASCII（GBK 环境的 pip 读不了中文注释）。

## 启动

```bash
.venv/Scripts/python.exe -X utf8 backend/app.py
# 打开 http://127.0.0.1:5000
```

启动时自动：建培训师相关 5 张表（含老库迁移）→ 60 秒后挂 Cookie 保活后台线程（30 分钟/轮，失效自动 OCR 重登）。

## Docker

```bash
docker build -t trainer-system:latest .
docker compose up -d     # 或 docker run -d -p 5000:5000 -v ./data:/app/data trainer-system:latest
```

- 镜像只含代码；`data/`（数据库、Cookie、凭据）通过卷挂载，不进镜像（见 `.dockerignore`）
- 容器内监听 `0.0.0.0`（`FLASK_HOST`/`FLASK_PORT` 环境变量可调）
- 运行机器仍需能访问内网（server1.tuwan.com / bigdata.tuwan.com）

## 系统结构

## 页面布局（绑定关系 = 首页）

- **顶部：新建绑定** — 先选类型（培训师 / 姐妹团三胎），两侧各输 UID 点「查询」自动带出昵称/大厅/等级（实时查 server1），未建档的绑定时自动建档
- **中间：档案入口卡** — 培训师档案、妹妹档案并列，点击弹出浮层管理：搜索/新增/编辑/删除/历史导入；妹妹表同时显示当前培训师与姐妹团姐姐
- **底部：绑定列表** — 当前生效/历史记录切换，类型筛选（全部/培训师/姐妹团）；每行含**结束日期**（奖励窗口终点）与**剩余奖励**（剩 N/4 周 / 未开始 / 已结束）标记，操作列可直接编辑两侧档案（编辑培训师/姐姐、编辑妹妹）、解绑、速查
- 所有列表（培训师/妹妹/绑定）均 20 条/页分页

## 绑定规则

- **培训师绑定**：一个培训师名额上限 5；同一妹妹同时最多一条生效培训师绑定
- **姐妹团三胎绑定**：一个姐姐同时只能绑一个妹妹（一对一，重复绑 409 提示换绑）；同一妹妹最多一条生效姐妹团绑定
- 两套绑定相互独立：同一妹妹可同时有一条培训师绑定 + 一条姐妹团绑定（数据库按 `(trainee_id, bind_type)` 部分唯一索引约束）
- 解绑不删记录，历史保留；有生效绑定时档案禁止删除

## 名额与奖励政策口径（代码实现位置 `backend/app.py` 顶部常量区）

**名额规则**（仅培训师绑定参与计算）
- 通过培训师考试 → 基础 2 个名额（档案 `base_slots`，默认 2 可改）
- 学员当月**当周等级**达标叠加：初银（初级银牌）+1 / 银牌+1 / 金牌+1（金牌学员一人 +3，即直升 5），总上限 5
- 实现方式：每次速查/刷新把学员当周等级 upsert 进 `trainee_level_monthly`（取当月最高），名额按当月最高等级计算 → 当月达标即解锁，次月未再达标则自然重置
- 与姐妹团名额/奖励相互独立（本系统只记培训师绑定）

**奖励规则**（仅培训师绑定；金额为单人份，实际 ×2 由培训师和新人各得一份，礼物形式赠送）
- **窗口：绑定次周周一 00:00 起整四周**（到第四周后的周一止），窗口外不产生奖励
- 周任务≥6次 + 铜牌及以上：12.8×2
- 晋升初银：12.8×2 / 晋升银牌：23.3×2 / 晋升金牌：52×2 / 晋升王牌：131.4×2
- 达标自动生成 `reward_grants` 待发放记录（UNIQUE(binding_id, reward_key) 防重），人工标记已发/可撤销

## 结果统计页

- **单人 UID 速查**（本周 vs 上周对比：等级/排档/任务/流水/排名），按 UID 身份自动带出判定面板：
  - 查**培训师** → **名额面板**：基础+额外=总名额、各学员贡献明细、超额提示；「刷新全部学员数据」逐个实时查询学员当周等级（0.6s 间隔，批量固定用 game 类型，其他类型请单查）
  - 查**妹妹** → **奖励面板**：窗口状态（未开始/剩余天数/已过期）+ 五档奖励状态，可标记已发/撤销
- Cookie 过期时自动 OCR 重登后重试一次（server1 会话 TTL 极短）

## 周奖励批量导出（XLSX）

结果统计页底部选「开始时间」→ 点「导出培训师奖励」或「导出三胎奖励」。与单人查询无关 —— 导出所选类型下**所有当前生效（在档）且奖励窗口未过期**的绑定，逐人实时查询（每人 2 次请求：当周+上周，0.6s 间隔，Cookie 过期自动重登一次）：

- 口径：完成任务次数/礼物流水 = 所选日期的上一周，牌子 = 所选日期当周（表头不带上/当周备注）
- 任务奖：周任务≥6次且当周铜牌及以上 → 12.8，否则「无」；等级奖：初银 12.8 / 银牌 23.3 / 金牌 52 / 王牌 131.4，其余「无」
- 表头第 3 行共 10 列：三胎奖励为「姐姐UID/姐姐昵称」，培训师奖励为「培训师UID/培训师昵称」，其余相同
- 文件名：`YYYYMMDD培训师奖励.xlsx` / `YYYYMMDD三胎奖励.xlsx`

数据口径：绑定关系只存在本系统（`data/stats.db` 的 bindings 表），不提交外部系统。
